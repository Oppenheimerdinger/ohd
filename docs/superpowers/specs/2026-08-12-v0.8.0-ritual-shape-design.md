## Part B — ritual shape (#38)

- **B1 fix-wave scope declaration — ONE home, r2c** (campaign-land already
  delegates the log format wholesale; zero campaign-land edit). r2c step 3
  gains one sentence and the log line one token: the round-N+1 line names
  what entered beyond repairs —
  `round 3: … @<sha> (fix wave: repairs only | +N additional: <one-clause reason>)`
  — additionals without a clause go to the follow-on line (the state-doc
  scaffold comment already routes review findings there; B1 composes with
  it). Rationale: review-prompted hardening is new code written under
  fatigue that reviews itself worst (field: rounds 3-7 entirely on such
  hardening, 81 lines deleted at the end; our own record has the same
  shape).
- **B2 the attestation layer gets one evidence-shaped pass.** The terminal
  round's INPUT includes the convergence log so far (in a campaign, plus
  the filled land-report rows — that half of the clause lives in
  campaign-land, which is uncapped). The terminal reviewer:
  (a) RE-RUNS every gate result quoted in them, reporting current output
  beside the quote — stale quote = finding; (b) checks each round's @sha
  exists and no two rounds share one (frozen-hash carve-out excepted);
  (c) checks every round line DECLARES provenance — a continued agent says
  `continued rN agent`, a model differing from the session's is named; an
  undeclared line reads as "fresh, session model" and that reading is the
  AUTHOR'S attestation, falsifiable later against the transcript. **The
  reviewer enforces that provenance is declared, not that it is true** —
  the honest maximum of in-harness evidence (a reviewer here cannot read
  transcripts, spawn timestamps, or model IDs; the draft's "verify against
  the agent record" was a paper check and is replaced by this). Field
  witness: three false attestations survived nine rounds — a "fresh"
  reviewer that was a continued agent, an undisclosed smaller-model
  terminal round, a stale gate quote; (a)/(b) catch the third and the
  sha class outright, (c) makes the first two lies-in-writing.
- **B3 the pre-registered revert bar, documented.** A 4-line paragraph
  inside r2c's Scope guard (its "unusually long run" sentence is the
  anchor): a NUMERIC trigger committed to the state doc BEFORE the round
  that could fire it, reviewer reports the count EVEN WHEN ZERO. Optional
  pattern, not mandated (trigger to mandate: a second field witness). One
  state-doc scaffold comment line rides C2's campaign.sh edit (comment-only;
  the parity mirror+smoke cost is paid once, by C2). Consistency verified:
  complementary to the moving-target stop (deliverable mutating) — the bar
  bounds optional-hardening churn on a FIXED deliverable; severity terminal
  untouched.
- **B4 finding→campaign promotion bar.** One way-of-working routing-table
  row: a review finding DEFAULTS to a backlog/follow-on line; opening a
  campaign for it requires naming why it cannot wait. (The follow-on
  routing half already exists in the scaffold comment; B4 adds only the
  bar.) No relay line of its own — folded into B1's.

## Part C — census & lifecycle

- **C1 (#34) runner-scope row (structure mode), narrowed three ways per
  review:** (1) `testpaths` ONLY — norecursedirs is a different parser
  class with no field witness (trigger to add: a case where it hides
  tests); (2) parser = section-scoped awk over `[pytest]`/`[tool:pytest]`
  ini keys and `[tool.pytest.ini_options]` toml incl. simple multiline
  arrays — ~30 lines bash/awk, NO python3 (checkup has none today); key
  present but extraction empty → MANUAL-CHECK naming the file;
  (3) candidate set = pytest-collectible files only (`test_*.py`,
  `*_test.py`) — never the census's VER_RE (a shell check "outside pytest
  scope" is a nonsense finding). **No-config or no-testpaths ⇒ pytest
  collects rootdir-wide ⇒ everything in scope ⇒ the row is SILENT** (fresh
  and small projects see nothing). The census scope note gains the honest
  line: a colocated dir the runner does not discover is invisible to the
  census — see this row. Field witness: 8 never-collected tests reading
  green; two sibling scar comments.
- **C2 (#37) opt-in post-create hook.** In `cmd_new`, after the state-doc
  write (cmd_new never commits, so the hook necessarily runs before the
  first commit — registration and doc land together): if
  `tools/campaign-post-create` exists and is executable, invoke it with the
  doc path; non-zero → new says so LOUDLY, doc stays (no rollback — the doc
  is the user's work; the hook's failure is the hook's news). Absent = zero
  behavior change. **CUT per review (security): the `CAMPAIGN_POST_CREATE`
  env var** — an out-of-repo channel (poisoned .envrc, CI env, shell
  profile) making routine `new` exec an arbitrary binary; the in-repo hook
  is the same trust class as campaign.sh itself; no witnessed need for the
  override (trigger: a project that cannot commit its hook). Body change →
  mirrored to tools/campaign.sh; smoke legs: present/absent/failing; B3's
  comment rides this diff.
  DEVIATION (implementation, 2026-08-12): a hook present but NOT executable
  warns instead of skipping silently — an unexecutable hook is the same silent
  no-op this hook point exists to end. Pinned at the same time: a failing hook
  leaves `new` exiting 0, because the worktree and branch already exist and a
  non-zero exit invites a retry that dies on "already exists".
