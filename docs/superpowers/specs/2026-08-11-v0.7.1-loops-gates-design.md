## Part 2 — loops ride OMC ralph; official ralph-loop dropped

- **2a Launch mechanics (THE load-bearing change — review's central
  finding, verified against the OMC source: a model-invoked ralph Skill does
  NOT arm the loop; state is armed only by the user-prompt keyword
  detector).** autonomous-mandate's launch step becomes:
  (a) arm state explicitly via OMC's sanctioned state tool —
  `state_write(mode="ralph", session_id, state={active:true, iteration:1,
  max_iterations:<cap>, prompt:<the mandate restated — the lane/advance/
  review-naming lines ride state.prompt and are re-injected verbatim each
  iteration>, project_path:<anchor>, started_at, last_checked_at})`;
  NO `awaiting_confirmation` field (it exists to gate keyword-armed state
  and would suppress the stop hook);
  (b) invoke the OMC ralph skill so the PRD machinery loads, writing
  step-1's done-contract INTO the PRD stories at arming;
  (c) **verify armed**: the next Stop must produce the ralph iteration
  banner — if it does not, the loop is NOT live; never proceed bare. The
  verify-armed probe is the contract; the state write alone is not trusted.
  DEVIATION (implementation, 2026-08-11): the call shape is
  `state_write(mode, session_id, active, iteration, max_iterations,
  started_at, state={session_id, project_path, last_checked_at, prompt})` —
  the first four ride TOP-LEVEL tool parameters (only custom fields take the
  `state` bag), and `session_id` is written in BOTH places because the tool
  parameter selects the path while the stop hook compares the id in the state
  BODY, so a body without one arms a file that blocks nothing.
- **2b Completion/cancel contract** (reworded per review — the draft was
  self-contradictory): mid-flight ABORT is user-owned, unchanged; the
  COMPLETION EXIT is the session running the OMC cancel command — legitimate
  ONLY after the verdict is banked. Order: all PRD stories pass → reviewer
  sign-off (the reviewer brief carries ohd's two mandatory questions AND the
  original mandate — the PRD is otherwise a self-authored yardstick) →
  verdict quoted VERBATIM into the state doc → then cancel. Cancel without a
  banked verdict is the new spelling of the unverdicted promise, named as
  such. Cap semantics honestly stated: OMC auto-extends the iteration cap —
  the evaluator exit, not the cap, is the terminator. State-file pointer
  updated to the OMC session-state path; the prompt-survives-compaction
  rationale and the "upgrading mid-mandate doesn't refresh a running loop"
  caveat carry over. DEVIATION (implementation, 2026-08-11): the
  "exact completion phrase" drops out of step 1's done-contract and the
  `<promise>` exit format drops out of step 3 — both were the dropped
  plugin's `--completion-promise` mechanism, and OMC's loop has no
  counterpart (cancel is the only exit), so keeping them would document a
  mechanism that does not exist.
- **2c Fallback + roster.** OMC absent → built-in /loop + schedule, with the
  honest capability note (no stop-hook persistence, no completion contract —
  mandate persistence in the state doc is the only durability there). The
  official ralph-loop tier is REMOVED everywhere. CUT (review): the
  uninstall suggestion — ralph-loop collides with nothing, and uninstalling
  under a still-running old mandate's loop file would kill it silently;
  dropping it from the roster is the whole change.
