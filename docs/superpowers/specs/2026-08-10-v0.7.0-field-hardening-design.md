## B — contract changes

- **B1 severity-anchored terminal — a MULTI-SITE sweep** (#21 §3, #22; the
  blindspot lens's top finding). The stop rule is restated at r2c:28 + the
  log-format terminal wording, way-of-working:40 + :258-259, campaign-land
  Phase 3 contract + example, deep-solve:65 + :213-215 — ALL move in one
  wave (v0.5.23's "one intervention across N surfaces" discipline; shipping
  r2c alone leaves two contradictory stop rules live, resolved ad hoc in the
  author's favor). New rule, replacement not addition: **terminal = a round
  returning zero Critical and zero Important, with every residual (Minor
  only — Critical/Important can never terminate as residuals) carrying a
  disposition.** When the terminal-candidate round is the first review of a
  substantially replaced artifact, one confirmation round on the frozen
  hash. The trigger is bound to an existing event, not judgment: the
  confirmation round is sanctioned EXACTLY when r2c's moving-target stop
  fired and the loop restarted on the replaced artifact — and it is the ONE
  sanctioned same-hash round (r2c's "same SHA is not a round" and
  campaign-land's duplicate-round line both gain the carve-out; fresh
  reviewer mandatory). CUT: the stop-rule-amendment corollary (meta-rule;
  trigger: a field report of a rule amended mid-loop to permit stopping).
  NAMED NON-SHIP: solve-converge.js's finding schema has no severity field —
  the runner cannot evaluate this terminal; the prose skill governs, runner
  alignment goes to backlog with that trigger. DECLARED RESIDUAL: severity
  labeling is uncalibrated (the terminal's robustness rests on reviewer
  C/I assignment; one field population observed). Revisit trigger: a shipped
  regression traces to an under-labeled finding in a terminal round.
- **B2 campaign-land reads CI** (#21 §2), ~5 lines in Phase 0, SCOPED: when
  the repo defines checks — `gh pr checks` green; the run must EXIST at the
  PR's head SHA (previous-commit state answers "zero incomplete" TRUE right
  after a push); green against the CURRENT base (carried as the one clause
  WITHOUT a field witness — the issue's own disclosure); required checks bind
  PRs, not admin direct pushes. ⚠ ordering: land the job first, require it
  second (branch-only required job = every PR permanently BLOCKED, no failing
  check to point at — measured). **No checks defined → state so and pass**
  (the fresh-project scaffold ships no CI; an unconditional clause is a
  permanently red precondition for every new project).
- **B3 gate/check deliverable row** (#21 §5). ONE r2c table row, ladder
  compressed in-row (verdict correct / tests match names — mutation only /
  what fixtures hold constant / which artifact is under test / does it bind /
  what is it about / how evaded / claims true / second environment). No body
  section (trigger: a field gate review that missed an axis the row names).
- **B4 verification-validity rule** (#22 G1; highest-yield). One cross-cutting
  line under the r2c table + one sentence: a verification NAMES the parameter
  it varies, and that parameter is the one the claim quantifies over; an
  instrument headed for a commit asserts its precondition and runs once in a
  deliberately degraded mode asserting the answer DIFFERS; a summary count
  may not include rows that cannot fail.
- **B5 deep-solve escalation carries a diagnosis** (#24 gap 2). One line at
  the escalation site + one line defining the buckets (problem statement /
  premises / acceptance apparatus), computed ad hoc; the shared log format is
  untouched. Apparatus-dominated ⟹ delete the apparatus, not patch it.
